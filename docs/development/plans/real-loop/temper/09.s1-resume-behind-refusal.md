# temper-09.s1 Owner work resumes behind a refused input

Added by ruling 131, from 09.2's diagnosis under ruling 129, for
session 09 (`09-loop-stories.md`): it runs before 09.2, which waits for it.

Scope: temper-service's engine host steps `Resume` while an input waits
refused, so that the owner work the domain refused it for drains and the
input is then admitted ("Owner progress is a step of its own. `Resume`
admits one", `docs/design/domain/root.md`, 4).
Needs: nothing landed beyond 09.1; the same session, before 09.2.
Files: `crates/temper-service/src/engine.rs`; one test file of
`crates/temper-service/src/tests/` (`clients_unwatch.rs` is the near one).
Shape: today `Engine::step` keeps a refused input in `pending` and sets
`blocked`; `release` steps `root::Event::Resume` only when `requests` is
empty and `!blocked`, and clears `blocked` only on an output or
`domain.quiescent()`, which needs `work` empty: a refusal behind owner
work (`Core::Notes::Loaded` in `domain.work`) never clears. Make
`release` step `Resume` when no output is held, `blocked` or not, and
retry `pending` once that work has drained; keep one output per call
and the order root.md 4 gives.
Test shape: `an_unwatch_refused_behind_owner_work_is_admitted`, under
20 ms: a `Party::Unwatch` refused while a notes load's continuation
waits in `domain.work`, then the engine's next passes: the load's work
drains and the Unwatch is answered, with no input left in `pending`.
Proof: unit, its test, and the land gate; 09.2's story is 09.2's proof.
Don't: change the engine domain's admission, skein or jig; retry in the
client; move 09.2's kill.
Size: about 15 production lines.
Removes: nothing.
